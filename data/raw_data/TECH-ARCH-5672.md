## 2. Core Policies and Standard Operating Procedures

### 2.1 Design Principles

* Separation of Concerns (SoC): Architects shall ensure that each component or layer is responsible for a specific aspect of the system.
* Single Responsibility Principle (SRP): Each module or component shall have a single, well-defined responsibility.
* Don't Repeat Yourself (DRY): Architects shall avoid duplicating code or logic whenever possible.

### 2.2 Software Architecture Standards

* Microservices Architecture: The company adopts a microservices architecture approach for new software development projects.
* Service-Oriented Architecture (SOA): Existing systems shall be designed using an SOA approach, where services are loosely coupled and can operate independently.

### 2.3 Development Methodologies and Tools

* Agile Development: The company adopts an agile development approach for all software development projects.
* Version Control Systems (VCSs): Git is the primary VCS used by the Architecture department.

### 2.4 Quality Assurance and Testing Procedures

* Unit Testing: Developers shall write unit tests for each component or module.
* Integration Testing: Integration testing shall be performed to verify that components interact correctly.
* Functional Testing: Functional testing shall be conducted to ensure that the system meets its functional requirements.

### 2.5 Change Management and Version Control Processes

* Request for Changes (RFCs): All changes to software systems shall be submitted through an RFC process.
* Code Reviews: Peer code reviews shall be performed for all changes before they are merged into the main codebase.

## 3. Compliance Monitoring, Penalties, and Operational Governance

The Architecture department shall govern the development and implementation of software systems according to this document.
